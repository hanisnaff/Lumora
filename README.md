**Lumora is an adaptive-learning demo that helps learners identify concept-level knowledge gaps, study focused lessons, practise weak areas, and track mastery over time.**

The currently implemented learning track is a hands-on **C++ pointers** demo. The assessment and learning path are generated by application logic and curated question content; Lumora does not currently provide an AI tutor or PDF-upload backend.

- **Guided learning flow:** setup → diagnostic assessment → knowledge-gap results → personalized lesson → targeted practice → progress dashboard.
- **Concept-level feedback:** review results and focus practice on weaker concepts.
- **Progress tracking:** local browser storage with optional cloud sync through Supabase.
- **Responsive UI:** React, TypeScript, Tailwind CSS, and custom learning visualizations.
- **Deployment-ready:** Vite frontend, Vercel serverless progress API, Supabase Auth, and Postgres.

## Product flow

1. Choose the C++ pointers learning track and difficulty.
2. Complete a diagnostic assessment.
3. Review concept-level results and identify weaker areas.
4. Study the lesson selected for the learner's weakest concept.
5. Practise with targeted questions and immediate feedback.
6. Review progress and repeat practice as needed.

## Run locally

**Requirements:** Node.js 20 or later and npm.

    git clone https://github.com/hanisnaff/Lumora.git
    cd Lumora
    npm ci
    npm run dev

Open the local URL printed by Vite. To type-check and create the production bundle:

    npm run build
    npm run preview

The frontend can run without cloud persistence; progress remains in local browser storage. The Vercel API routes are intended to run on Vercel. To test those routes locally, use the Vercel CLI with the environment variables configured.

## Supabase setup

Lumora is configured with the public URL and publishable key for its connected Supabase project. These are public client values, not secrets. You can override them when using a different project.

1. Open Supabase **Authentication** settings and enable **Anonymous Sign-Ins** so learners can try the demo without creating an account.
2. Ensure email/password authentication is enabled if you want learners to create accounts and sign in.
3. In **URL Configuration**, set the Site URL and add the exact app callback URLs to the Redirect URLs allow list, including your deployed app's `/auth` route and `http://localhost:5173/auth` for local development. Password recovery returns to `/auth` to let the learner set a new password.
4. Confirm that the **public.learning_progress** table exists. If needed, run [supabase/schema.sql](supabase/schema.sql) in the Supabase SQL Editor. The script can be safely re-run.
5. The table uses row-level security (RLS). Authenticated sessions can read or modify only the row whose **user_id** matches their own Supabase user ID.
6. Open the app and complete an assessment or practice session. Confirm that a row appears in **public.learning_progress**.

### Environment variables

The app has public defaults for its connected Supabase project. Set these variables only when overriding that project or configuring a separate environment:

| Variable | Runtime | Purpose |
| --- | --- | --- |
| VITE_SUPABASE_URL | Browser | Supabase project URL |
| VITE_SUPABASE_ANON_KEY | Browser | Supabase publishable/legacy anon key |
| SUPABASE_URL | Vercel API | Supabase project URL |
| SUPABASE_ANON_KEY | Vercel API | Supabase publishable/legacy anon key |

Copy [.env.example](.env.example) as a reference. **Never put a service-role or secret API key in a VITE_* variable, commit secrets, or paste secrets into issues.** The current API uses the learner's access token and database RLS rather than a service-role key.

## Deploy to Vercel

1. Import [hanisnaff/Lumora](https://github.com/hanisnaff/Lumora) into Vercel.
2. Keep the framework preset as **Vite**. The repository's vercel.json configures the build output and client-side routing fallback.
3. If using the default Supabase project, no extra environment variables are required. Otherwise, configure the four variables above for the relevant environments.
4. Deploy the latest main branch.
5. Open **https://YOUR-DEPLOYMENT.vercel.app/api/health**. A healthy response should contain **ok: true**, **databaseConfigured: true**, and **databaseReachable: true**.
6. Complete a learning activity and verify that a row is created or updated in Supabase **public.learning_progress**.

If the health endpoint reports that the table cannot be queried, rerun **supabase/schema.sql** and check the table grants. If anonymous sign-in fails, confirm that **Anonymous Sign-Ins** is enabled in Supabase Auth. If account creation, sign-in, or password recovery fails, check the email/password provider settings and make sure the app's `/auth` callback URL is allow-listed.

## API reference

### GET /api/health

Checks whether the API can reach the progress table. It does not return credentials.

### GET /api/progress

Requires a valid Supabase access token in the Authorization: Bearer <token> header. Returns the current learner's saved state or null if no state exists.

### PUT /api/progress

Requires the same authentication header and a JSON body of the form:

    {
      "state": {
        "selectedSubject": "C++",
        "selectedTopic": "Pointers"
      }
    }

The example is abbreviated; the application stores the full learning state. Requests are limited in size and row access is enforced by Supabase RLS.

## Security notes

- Browser-visible Supabase publishable keys are expected to be public; RLS is the access-control boundary.
- The API validates each access token with Supabase before accessing progress.
- Progress requests use the learner's token when querying Postgres, so row-level policies enforce ownership.
- Do not add service-role keys, database passwords, or other secrets to source control.
- See [SECURITY.md](SECURITY.md) for reporting a vulnerability.

## Current scope and roadmap

**Implemented:** C++ pointers learning flow, diagnostic scoring, concept mastery updates, targeted practice, local persistence, optional Supabase cloud persistence, Vercel API health check, and CI build verification.

**Not implemented yet:** full account registration/recovery, cross-device account linking, PDF upload and parsing, a generative AI tutor, additional complete subject curricula, and an independently deployed AI backend. The app should not be presented as having these features until they are built and tested.
